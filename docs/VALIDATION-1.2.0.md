# v1.2.0 验证记录

验证对象：MSVC 14.44 编译的原生 x64 程序，版本 1.2.0，最终 EXE 为 172,032 字节（168 KiB），构建无编译警告。交付包使用最终发布构建文件，不含诊断标记或原始日志。

环境：Windows 11 IoT Enterprise LTSC x64，10.0.26100，100% 显示缩放。目标为两个系统经典记事本的空白窗口（下文 A、B）。本记录公开功能证据，不发布原始截图、窗口列表、个人文档内容或诊断日志。

## 功能验证

完整引擎与界面回归后，最后仅修正了数量徽标在颜色不变、数量改变时的重绘。修正后的最终发布构建再次完成下方单列验证。两次构建使用相同的尺寸恢复引擎。

| 操作 | 实测结果 |
| --- | --- |
| 选取 A | 读取外部尺寸 1023 × 790，加入管理 |
| 手动缩小 A | 应用 900 × 650，设定与实际一致 |
| 追加 B | B 独立记录 2360 × 1400，A 保留 |
| 只暂停 B | B 可自由调整，A 仍恢复自身设定 |
| 只启用 B | B 恢复自身的固定尺寸 |
| Ctrl / Shift 多选管理 | 两目标同时暂停显示 0/2，启用显示 2/2，尺寸记录保留 |
| 手动放大 A | A 变为 1100 × 750，B 仍为 2360 × 1400 |
| 输入宽度 0 | 提示有效范围；原设定和实际尺寸不变，输入不会被后台覆盖 |
| 一键读取 B 最大化尺寸 | 记录实际外部尺寸 2360 × 1400 |
| 移动普通状态的巨窗 B | 移动生效，没有强制返回旧位置 |
| B 点击最大化按钮 | 最大化状态保留，外部尺寸 2360 × 1400，左上角 (-8,-8) |
| B 拖标题到屏幕顶部 | Windows 顶部吸附成功，最大化状态稳定，没有程序强制还原记录 |
| A 普通尺寸点击最大化 | 还原至设定的 1100 × 750；该次最大化检测到还原请求的日志时间差约 47 ms |
| A 最小化与还原 | 最小化暂停纠正，还原继续固定 1100 × 750；B 持续固定 |
| 移除 A | 只保留 B 的固定 |
| 蓝色按钮拖动重新追加 A | 正确追加，B 保留 |
| 收起与再次运行 | 唤回同一面板，只有一个进程，已有记录保留 |
| 退出 | 解除全部目标，进程终止 |

上述时间只描述具体操作，不是所有机器上的响应保证。拖动期间可短暂改变尺寸，松开后等待约 200 ms 状态稳定再恢复。

## 尺寸含义

| 本机测量项目 | 尺寸 |
| --- | --- |
| 屏幕 rcMonitor | 2344 × 1432 px |
| 最大化工作区 rcWork | 2344 × 1384 px |
| 记事本最大化 GetWindowRect | 2360 × 1400 px，左上角 (-8,-8) |
| DWM 可见外框 | 2344 × 1384 px |

外部矩形包含隐形调整边框，因此最大化外部尺寸可以比工作区大。新版比较实际最大化尺寸，匹配时保留最大化，并在移动、缩放结束后等待系统状态稳定，避免与 Windows Snap 争用。手动输入工作区或屏幕尺寸也允许最大化边框差异；该输入分支经过代码检查，但本次顶部吸附实测使用的是记事本真实最大化外部尺寸。

## 最终发布文件资源采样

面板收起到托盘，两个目标开启且静止，无桌面辅助功能轮询。采样使用进程 CPU 时间与内存计数。

| 指标 | 数值 |
| --- | ---: |
| 采样时长 | 20.0289334 秒 |
| CPU 时间增量 | 0.234375 秒 |
| 占单逻辑处理器时间比例 | 约 1.17% |
| 专用内存 | 3,145,728 字节，3.00 MiB |
| 工作集 | 20,684,800 字节，约 19.73 MiB |

CPU 计数有时间分辨率限制；工作集和专用内存随系统回收、绘制及运行状态变化。本样本不代表持续拖动、可见面板或所有电脑，也不证明 CPU 长期恒定。
