# v1.3.1 验证记录 · 2026-11-10

验证对象：MSVC 14.44 `/O1 /MT /W4` 编译的原生 x64 程序，文件版本和产品版本均为 1.3.1。构建无编译警告，最终 EXE **182,784 字节（178.5 KiB）**。以下新版交互测试使用同一最终二进制，发布包包含该文件。

EXE SHA256：`38078fb593abb42df9759670fbfe627ebd4f6f8821cfa8e8abc91b31ae0ff959`。

环境：Windows 11 IoT Enterprise LTSC x64，10.0.26100，100% 显示缩放；当前屏幕 **2344 × 1432 px**，扣除任务栏后工作区 **2344 × 1372 px**。使用任务创建的原生受限最大化测试窗口与空白经典记事本，不编辑个人文档、不操作虚拟机。本机仅有 VMware Tools，未安装 VMware Workstation，不能将模拟结果标记为实际 VMware 验证。

## 确认的工具缺陷与修正

用户反馈：其他窗口最大化后的外部尺寸为 2582 × 1622，VMware 为 2564 × 1604；点击最大化后被还原或尺寸反复变化。这些数字来自用户反馈，与本轮测试电脑的显示配置不同。

代码审查发现 v1.3.0 的最大化捕获要求：目标已最大化、矩形及状态稳定、DWM 可见外框覆盖工作区。自定义边框或 `WM_GETMINMAXINFO` 限制可能产生合法的较小最大化范围。旧条件会拒绝捕获，2500 ms 超时后恢复旧固定尺寸；最大化位置修复也会把未覆盖工作区视为异常。这是已确认的工具兼容缺陷，不能仅凭 18 px 数字差异断定 VMware 的具体实现。

v1.3.1 接受目标处于最大化状态且稳定、可见外框在工作区及目标 DPI 系统边框容差内的实际尺寸。覆盖工作区仅用于状态说明；较小但处于合法范围内的最大化窗口不触发还原。越出工作区及边框容差时仍保留有次数上限的修复。捕获成功后保存“允许此窗口自身最大化”模式，配置格式仍为版本 1。

## 旧版故障复现与新版对照

测试窗口通过原生 `WM_GETMINMAXINFO` 将最大化外部宽、高限制为工作区各减 18 px，最大化位置为工作区左上角。初始普通尺寸 900 × 650。这个窗口模拟自定义最大化限制，不模拟 VMware 的全部窗口实现。

| 项目 | 实测结果 |
| --- | --- |
| 测试窗口最大化外部尺寸 | 2326 × 1354，位置 (0,0) |
| 测试窗口最大化 DWM 可见外框 | 2308 × 1336，小于工作区 |
| v1.3.0 先固定 900 × 650，再点击读取最大化 | 短暂最大化到 2326 × 1354；约 2.5 秒后被还原到 900 × 650，提示目标未响应最大化 |
| v1.3.1 同条件点击读取最大化 | 成功记录 2326 × 1354，显示允许此窗口自身最大化；越过旧版超时后持续保持 |
| 通过系统菜单还原为普通窗口 | 工具将临时的 900 × 650 恢复到记录的 2326 × 1354，保持普通状态 |
| 再次点击最大化按钮 | 最大化状态 2326 × 1354 保持，没有误还原或尺寸循环 |
| 最小化后恢复 | 记录保留，目标恢复自身最大化尺寸 |
| 退出、重启工具 | 自动连接测试窗口，2326 × 1354 与允许最大化模式均保留 |

旧版诊断观测到最大化 2326 × 1354 后出现 `RESTORE_FROM_MAXIMIZED`，随后为普通状态 900 × 650。新版成功捕获后的最大化观测为 `max=1 want=2326x1354`；正常还原后的尺寸纠正符合记录，随后再次最大化保持该尺寸。界面观察与诊断交叉核对。窗口激活操作有时会使 Windows 还原目标，因此再次最大化的最终状态以明确操作后的新观察与诊断为准。

## 升级与实际 VMware 验证步骤

1. 退出旧版工具，运行 v1.3.1。原 v1.3.0 设置采用相同格式，会继续载入。
2. 在管理列表中选中 VMware Workstation，再点击“使用此窗口的最大化尺寸”。不要把其他程序的外部尺寸输入给 VMware。
3. 若其自身最大化后为 2564 × 1604，应记录该尺寸，并出现“允许此窗口自身最大化”。即使旧记录数字已经相同，也重新读取一次确认模式。
4. 还原、再次点击最大化，观察是否保持自身最大化状态；也可检查顶部拖动吸附。当前本机没有 VMware，以上为实际目标的验证步骤，不是已执行结果。
